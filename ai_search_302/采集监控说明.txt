批量采集与监控

当前任务：122个审核问题 × 豆包、DeepSeek、Qwen，共366份回答。
先以海南游客证件问题试采集3份；取得正文和平台来源后继续，其结果计入366份。
并发数为3。每个请求独立，统一提示词、查询日期和搜索服务；原始响应同步保存。
密钥读取自AI302_API_KEY环境变量或本目录.env文件，支持变量赋值或单独一行密钥。

从项目根目录运行：

1. 查看当前进度
   python .\ai_search_302\monitor_302.py

2. 持续监控（默认每5秒刷新）
   python .\ai_search_302\monitor_302.py --watch

3. 获取进度JSON
   python .\ai_search_302\monitor_302.py --json

4. 请求停止新增任务
   python .\ai_search_302\monitor_302.py --stop
   已在进行的请求会先保存。Ctrl+C退出监控只关闭监控，不会停止采集。

5. 续跑
   python .\ai_search_302\collect_302.py run "监控显示的完整采集目录"

   默认跳过所有已落盘的回答（包括需要人工核查的回答和已记录的接口失败）。
   如果需要额外重试接口失败，或中断时请求已发出但未落盘，先查看平台调用日志，再使用：
   python .\ai_search_302\collect_302.py run "采集目录" --retry-failed

   重试另存为新attempt，不覆盖原结果。断点续跑仍使用该批次冻结的提示词和日期。
   同一目录只能运行一个采集进程，操作系统文件锁随进程退出释放。

6. 创建新一轮任务（只建任务，不会立刻扣费）
   python .\ai_search_302\collect_302.py prepare --cards ".\新闻来源整理_2026-11-13\新闻卡片.json"
   然后使用第5项命令启动新目录。

采集目录：
  collection.json  本轮参数、提示词、日期与文件校验值
  tasks.json       本轮任务清单（只含问题，不含核查事实）
  answers/         可直接处理的回答JSON
  raw/             实际请求正文与完整响应
  events.jsonl     只追加的运行日志与心跳
  control.jsonl    启动/停止指令
  stdout.log、stderr.log  后台运行输出（后台启动时）

监控中的“有正文与来源”仅表示接口结构完整，不代表事实正确。
待核包含来源缺失、截断或拒答等情况。接口失败和待核结果同样保留。
账号或额度错误、限流，以及连续5个接口错误会停止新增请求，避免继续消耗。
监控不调用AI API，不产生搜索费用；预计剩余时间只是基于已完成耗时的粗估。
